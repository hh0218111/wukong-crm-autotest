## 三、迁移中发现并修复的问题

### 框架侧（我自己的实现缺陷）

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | 接口用例跑到后半段全部 `code:101 请先登录` | 悟空CRM **单点登录**：源码 `admin/model/User.php` 登录时 `Cache::rm('Auth_'.$userInfo['authkey'])` 主动删旧会话。登录模块用例自己登录一次就把 session fixture 的会话踢了 | 引入 `SessionHolder`，检测到 101/302 自动重登并重试 |
| 2 | 回款三条缺陷用例全部 XPASS（假通过） | 挑合同只按 `money>0`，选到未审核合同 → 返回「合同未审核通过」，**在金额校验之前就被拦下**，等于没测到目标规则 | 改为筛 `check_status=7`（已审核）的合同 |
| 3 | 客户数据清理静默失效 | `CustomerApi.delete` 无脑再包一层列表：`[244]` → `{"id":[[244]]}`，服务端解析失败返回空 body | 与其他模块统一 `isinstance` 判断 |
| 4 | 清理时 `JSONDecodeError` | `raw()` 已做鉴权重试，`post()` 又判断一次 → **删除请求被发两遍**，第二遍数据已不存在 | 重试只保留在 `raw()` 一层 |
| 5 | 失败截图钩子对新增 fixture 失效 | 只认 `page`/`logged_in_page` 两个固定名 | 改为按对象类型识别任意 Page |

> 第2条最值得讲：**反向用例必须确保前置条件成立**，否则"被拦截"可能拦的是别的规则，
> 用例会假通过。这是 xfail(strict=True) 帮我抓出来的 —— 它把"意外通过"变成失败。

## 四、实测确认的接口契约

| 项 | 结论 |
|---|---|
| 后端入口 | `http://localhost/72crm/index.php` |
| 前端入口 | `http://localhost/72crm/index.html#/login`（独立 SPA，hash 路由） |
| 鉴权 | 自定义头 `authKey` + `sessionId`，用 `Authorization` 返回 101 |
| 会话机制 | **单点登录**：同账号再登录会使旧 authKey 立即失效 |
| 成败判定 | HTTP 恒 200，业务码 200成功 / 400校验失败 / 101、302未登录 |
| 唯一性校验 | `name`、`mobile` 均有；重复提交返回 400「该字段值重复」 |
| 删除参数 | `id`（不是 ids），且必须是**扁平**数组 |
| 合同审核 | `check_status=7` 为通过；未审核合同无法回款 |
| 线索字段 | `name`（不是 customer_name），DB `varchar(255)` |
| 登录页选择器 | `input[placeholder='请输入用户名']`、`.login-by-pwd .btn`（是 div 不是 button） |
| SPA 等待 | hash 路由不触发 navigation，需 `wait_for_function` 轮询 hash |
| 登录后弹窗 | 有升级/引导弹窗遮挡，必须关闭否则业务用例点不到元素 |

## 五、环境注意

`php-cgi` 单进程在连续请求下偶发 502 / 空响应。启动时建议带 worker：

```bash
PHP_FCGI_CHILDREN=4 PHP_FCGI_MAX_REQUESTS=1000 ./php-cgi.exe -b 127.0.0.1:19000 &
```

客户端对 502/503/504 与空 body 重试一次（环境抖动），但**业务性 500 不重试**——
那是被测缺陷，必须如实暴露。
