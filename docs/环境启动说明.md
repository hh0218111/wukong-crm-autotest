# 本机悟空CRM 环境启动说明

环境是 phpstudy 套件，装在 `D:\phpstudy_pro`。**四个服务缺一不可**，
少起一个就会报错（2026-11-17 逐个踩坑确认）。

## 一、最省事的方式

打开 phpstudy 面板，把 MySQL、Nginx、Redis 都点启动即可。
下面是面板不可用时的命令行启动方式。

## 二、命令行逐个启动（Git Bash）

```bash
# 1. MySQL（3306）
cd /d/phpstudy_pro/Extensions/MySQL5.7.26
./bin/mysqld.exe --defaults-file="D:/phpstudy_pro/Extensions/MySQL5.7.26/my.ini" &

# 2. Redis —— 注意端口和密码！CRM 配置要的是 16379 + 密码，不是默认 6379
cd /d/phpstudy_pro/Extensions/Redis
./redis-server.exe --port 16379 --requirepass 123456 &

# 3. PHP-CGI（19000，Nginx 转发目标）
cd /d/phpstudy_pro/Extensions/php/php7.3.4nts
./php-cgi.exe -b 127.0.0.1:19000 &

# 4. Nginx（80）
cd /d/phpstudy_pro/Extensions/Nginx1.15.11
./nginx.exe -p "D:/phpstudy_pro/Extensions/Nginx1.15.11/" &
```

## 三、验证环境是否就绪

```bash
netstat -ano | grep -E ":(3306|16379|19000|80) "   # 四个端口都应在 LISTENING
curl -s -o /dev/null -w "%{http_code}\n" http://localhost/72crm/   # 应为 200
```

## 四、访问信息

| 项 | 值 |
|---|---|
| 后端入口 | `http://localhost/72crm/index.php` |
| 站点根目录 | `D:\phpstudy_pro\WWW\72crm` |
| 管理员账号 | 见本地 `.env` 的 `CRM_ADMIN_USER`（数据库 `5kcrm_admin_user` 表可查） |
| 管理员密码 | 见本地 `.env` 的 `CRM_ADMIN_PASS` |
| 数据库 | `5kcrm`，表前缀 `5kcrm_`，root@127.0.0.1:3306 |

> 凭据一律不写进仓库：`.env` 已在 `.gitignore` 中，数据库密码在
> `WWW/72crm/config/database.php`，`.env` 从那里同步。
>
> **本地环境找回密码的方法**（不改库、不重置）：悟空CRM 的密码存储是
> `md5(sha1(pwd) + md5(pwd+salt))`，可拿常见弱口令逐个算哈希与库中值比对。
> 实测本机管理员用的是弱口令 —— 这本身就是"测试环境弱口令"的真实案例，
> 生产环境务必强制复杂度策略。

## 五、踩过的坑（排错顺序参考）

| 现象 | 原因 | 解决 |
|---|---|---|
| HTTP 500 `RedisException` | Redis 没起 | 启动 Redis |
| 起了 Redis 仍 500 | 起在默认 6379 无密码，但 CRM 要 16379 + 密码 123456 | 按 CRM 配置重启 |
| 首页只返回"悟空软件"四个字 | 这是纯后端 API，前端 Vue 是独立工程 | 接口测试直接用 index.php 入口 |
| 接口返回 `code:101 请先登录` | 用了标准 `Authorization` 头 | 改用 `authKey` + `sessionId` |
| 用例第二次跑就失败 | `name`/`mobile` 有唯一性校验 | 用例加 RUN_ID 后缀 + 动态手机号 |

## 六、注意

- 这是**本机测试环境**，数据可随意造，但用例仍应自清理（框架已实现 `created_ids` fixture）
- 端口 80 上可能有其他程序占用，若 Nginx 起不来先查 `netstat -ano | grep ":80 "`
- `.env` 不进 git，换机器时重新按本文件确认各项值
